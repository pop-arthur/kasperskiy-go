## Функциональные требования

- Хранить сведения об угрозах; уникальный идентификатор — MD5 файла.
- Получать, создавать и обновлять записи тремя заданными операциями.
- Проверять MD5 и тело запроса; отклонять дубликаты при создании.
- «Перед реализацией необходимо дополнить модель угрозы полями»:
  в контракт добавлено description и серверные created_at/updated_at.
- Удаление, список угроз и сканирование файлов не входят в задачу.

## Нефункциональные требования

- Go, REST API, прагматичная Clean Architecture, DI через конструкторы.
- Конфигурация через окружение, structured logging, минимум зависимостей.
- Unit/integration tests, воспроизводимая Docker-сборка и документация.
- PostgreSQL для постоянного хранения — принятое проектное решение,
  не исходное обязательное требование задания. Одна таблица threats.
- Уникальность MD5 обеспечивает БД, включая конкурентные POST.
- Читаемый идиоматичный код, сохранение совместимости согласованного API.
- Генерация по OpenAPI, rate limiting, TLS и авторизация не выбраны.
  Требования к нагрузке, задержкам и доступности не предоставлены.

## Контракт API 1.1.0

| Метод и путь | Действие | Успех | Ошибки |
| --- | --- | --- | --- |
| GET /info/{md5} | Получить угрозу | 200 | 400, 404, 500 |
| POST /info | Создать угрозу | 201 | 400, 409, 500 |
| PUT /info/{md5} | Заменить изменяемые поля существующей записи | 200 | 400, 404, 500 |

Тела запросов и ответов — application/json. POST/PUT принимают один JSON-объект.

| Поле | POST | PUT | Успешный ответ |
| --- | --- | --- | --- |
| md5 | Обязательная строка | Только в пути | Обязательная строка lowercase |
| name | Обязательная строка | Обязательная строка | Обязательная строка |
| description | Необязательная строка | Необязательная строка; отсутствие удаляет описание | Строка или поле отсутствует, если в БД NULL |
| created_at | Сервер назначает | Не меняется | Обязательный readOnly date-time |
| updated_at | Сервер назначает, равно created_at | Сервер обновляет при каждом успешном PUT | Обязательный readOnly date-time |

Правила:

- MD5: ровно 32 ASCII hex-символа, исходный pattern `^[a-fA-F0-9]{32}$`.
  Принимать оба регистра, затем приводить A–F к lowercase во всех операциях.
  Пробелы не обрезать. Регистр не влияет на уникальность или поиск.
- name/description: строки без null и U+0000; пустые строки и пробелы допустимы,
  сохраняются без trim. minLength/maxLength не вводятся.
  Запрет U+0000 — уточнение совместимости с PostgreSQL text.
- Неизвестные поля запросов разрешены и игнорируются. Клиентские даты и md5
  в теле PUT не меняют запись; идентификатор PUT берётся исключительно из пути.
- POST без description сохраняет SQL NULL. PUT полностью заменяет name и
  description; отсутствие description сбрасывает его в SQL NULL.
  Явный JSON null недопустим; пустая строка отличается от отсутствия.
- Даты в ответах — RFC 3339 в UTC с суффиксом Z. Время назначает БД.
  updated_at не является номером версии или гарантированно возрастающей меткой.
- PUT отсутствующей записи не выполняет upsert. Конкурентные PUT используют
  семантику последней успешной записи без проверки версии.
- Ошибки всегда содержат строковые message и details; details может быть пустой.
  400 — ошибка входных данных, 404 — запись отсутствует, 409 — дубликат POST,
  500 — внутренняя ошибка без SQL, секретов и технических подробностей.

## Ограничения

Текущий этап — запуск API по согласованному плану: config, pgxpool startup
и проверка схемы, signal/graceful shutdown, Compose API и process/container
smoke tests. Runtime defaults описаны в [RUNTIME.md](backend/RUNTIME.md);
это проектные решения, не исходные требования Kaspersky. Новых endpoints,
зависимостей и изменений бизнес-контракта нет; миграции отдельные.
Не добавлять фиктивные тесты, вымышленный module path и лишние сервисы.
Java/Spring из пересказа не применять: пользователь выбрал Go.

severity/category/first_detected_at, их enum/default, безопасность и новые
эндпоинты не входят в принятую модель v1. created_at — создание записи,
а не первое обнаружение угрозы.

## Критерии приёмки будущей реализации

- Все три операции соответствуют актуальной OpenAPI, статусам и JSON-схемам.
- Некорректные MD5/JSON, отсутствие обязательных полей, неверные типы,
  null и U+0000 в известных строковых полях дают 400.
- Дубликаты MD5, включая иной регистр и конкурентное создание, дают 409;
  PUT/GET отсутствующей записи дают 404, PUT ничего не создаёт.
- PUT соблюдает замену description и неизменность md5/created_at.
- Серверные даты корректны; SQL NULL не сериализуется как JSON null.
- Неизвестные поля и клиентские даты не сохраняются.
- Данные сохраняются после перезапуска с постоянным томом PostgreSQL.
- Поведение проверено unit/integration tests; Docker-запуск документирован.

Официальной шкалы оценки Kaspersky нет; это проверяемые условия,
выведенные из контракта и принятых решений.
